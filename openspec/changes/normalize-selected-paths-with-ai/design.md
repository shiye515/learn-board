## Context（上下文）

Canvas Room 将徒手笔画存储为世界坐标中的 `StrokeElement` 点数组。当前选区操作可以生成类似 SVG 的路径字符串，但只会输出到控制台，不会修改文档。应用已经使用 TanStack Start，并以 Cloudflare Workers 为部署目标；`wrangler.jsonc` 也已声明 `AI` 绑定。

新流程将跨越浏览器、类型化 TanStack Start 服务端边界、Cloudflare Workers AI、确定性几何重建、文档历史和本地持久化。模型输出不能直接作为文档数据使用：必须经过 Schema 校验、置信度门控，并由应用代码转换为几何图形后，才能替换用户笔画。

Cloudflare 文档提供了本方案使用的核心集成点：Worker 代码通过 `env.AI` 访问 Workers AI，并可通过模型原生 `guided_json` 约束结构化输出。本地开发期间调用 Workers AI 仍会访问 Cloudflare 账户并产生用量。

生产推理模型确定为 Cloudflare 托管的 `@cf/mistralai/mistral-small-3.1-24b-instruct`。该模型支持视觉输入和 `guided_json`。请求同时提供简化路径点和仅由选中路径生成的单色预览图：点数据用于保留精确拓扑，预览图用于提升几何图形及未枚举生活符号的识别可靠性。

## Goals / Non-Goals（目标与非目标）

**目标：**

- 识别选中的标准几何图形（包括五角星），并允许 AI 推断未预先枚举的生活常用符号，将其替换为安全、规整的矢量路径。
- 保持选中图形的中心和视觉占用范围，以及精确的笔画颜色、粗细、层级顺序、撤销/重做和自动保存行为。
- 将 Workers AI、Rate Limiting 和 Cloudflare 绑定限制在仅服务端边界内，只发送必要的选中几何和选区单色预览。
- 所有模型响应在通过严格 Zod Schema、支持图形检查、置信度检查和源数据时效检查前均视为不可信。
- 使用采样后的 `StrokeElement` 点表示标准化图形，保持现有版本 1 白板文档兼容。
- 提供清晰的处理中和成功反馈；无法推断、低置信度、模板无效、超时、限流或一般错误时显示 Toast，并保持原图不变。

**非目标：**

- 本次变更不自动标准化每一条完成的笔画，也不增加类似 iOS 的长按手势。
- 首个版本不识别手写文字、便签文本、复杂任意插画或要求语义理解的场景图；常用符号是否可转换由模型置信度和矢量模板校验共同决定。
- 不向推理服务发送完整白板、视口、便签内容、本地持久化载荷、笔画颜色或 Cloudflare 凭据。
- 不允许模型返回可执行代码或直接生成白板元素。
- 不新增远程白板存储、协作系统或文档 Schema 版本。

## Decisions（决策）

### 1. 使用类型化服务端函数和原生 Workers AI 绑定

选框按钮调用 TanStack Start POST 服务端函数。共享请求/响应 Schema 放在不依赖运行时的模块中；推理适配器使用 `.server.ts` 后缀，并仅在其中从 `cloudflare:workers` 导入 `env`。处理器直接通过 `env.AI.run` 调用 `@cf/mistralai/mistral-small-3.1-24b-instruct`，显式传递 data URL 图片、模型原生 `guided_json` 和生成参数，再使用 Zod 校验结果。服务端函数继续受 `src/start.ts` 中现有 `createCsrfMiddleware` 保护。

这样可以避免凭据和运行时绑定进入客户端包，保持现有 TanStack Start 应用模型。直接从浏览器调用 Workers AI REST API 会暴露凭据并绕过应用校验边界，因此不采用。实测通用 Provider 将结构化参数映射为 `response_format` 时，该模型可能返回不可解析文本或错误的 `unsupported`；因此原生 `env.AI.run` 是唯一生产调用路径，而不是后备。不得静默切换模型。

响应解析允许 Workers AI 返回 JSON 字符串、已解析对象，或包裹在短说明中的唯一分类 JSON；恢复出的字段仍必须通过同一严格 Zod Schema。该兼容层只读取模型已经给出的 `category`/`shape`/`label` 语义，不根据本地点数据猜测类别。

### 2. 使用“已知图形策略 + 受约束 AI 矢量模板”的混合输出

模型接收简化、归一化的点和预览图。第一阶段只返回扁平紧凑的分类结果：

```ts
type ModelClassification = {
  recognizable: boolean
  category: KnownShape | 'common-symbol'
  symbolName: string
  confidence?: number
}
```

对于已知图形，AI 只负责分类，本地确定性策略负责重建。模型可能在正确分类时省略 `confidence`；此时可识别结果使用保守默认值 `0.9`，不可识别结果使用 `0`。只有第一阶段返回 `common-symbol` 时，服务才进行第二次 AI 调用并请求单位坐标矢量模板，从而避免让单个巨大联合 Schema 同时承担分类和复杂 DSL 生成。该模板不是 SVG 文本、代码或白板元素，只能由有限的移动、直线、二次曲线和三次曲线段组成。

服务端和客户端都必须使用严格 Schema 校验模板。`symbolName` 必须是 1–64 字符的小写 ASCII slug；每次响应最多 8 条路径、总计最多 32 个段、采样后最多 512 个点。每条路径必须以且只能以一个 `move` 开始，随后至少包含一个可绘制段；端点坐标必须位于 `[0, 1]`，二次/三次曲线控制点允许位于 `[-0.25, 1.25]`。未知字段、非有限坐标、越界坐标、空路径或复杂度超限均视为无效。

通过 Schema 校验后，客户端先对模板可见几何边界重新归一化，再以原选区的轴对齐边界进行缩放和平移；模板必须保持预览图中观察到的方向，客户端不对未枚举符号额外旋转，避免重复旋转。曲线使用自适应细分，每段最多 16 个采样点，且必须遵守 512 点总上限。任何模板都不得携带颜色、粗细、ID、事件处理器、URL、脚本或任意 SVG 标记。

这种混合方式让常见但未列举的符号具备扩展空间，同时将 AI 自由限制在安全的小型矢量 DSL 中。阿拉伯数字、拉丁字母和基础数学运算符也走同一常用符号流程，分别使用稳定的 `digit-*`、`letter-uppercase-*`、`letter-lowercase-*` 和 `math-*` 标识，不在客户端维护字符或符号的本地分类器或模板。应用继续使用类型化图形策略注册表管理已知标签；新增确定性图形时只需扩展标签、策略和测试夹具，不改变服务端函数、历史记录或持久化流程。

### 3. 归一化并限制请求载荷

只有选中的笔画元素具备资格。便签永不包含在载荷中。选区可以包含一条笔画，或少量颜色与粗细完全一致的笔画；混合样式或包含便签的选区会在推理前被拒绝。

调用服务端前，客户端将：

1. 计算由选中元素 ID 和点数据组成的不可变指纹。
2. 将点转换到选区局部坐标，并缩放到单位边界框。
3. 使用确定性线段简化算法减少点数，同时保留闭合关系和主要极值点。
4. 移除压力、颜色、时间戳、ID、世界坐标位置和无关文档数据。
5. 将所有选中笔画按轴对齐选区等比缩放并居中渲染为 256×256 PNG：白色背景、黑色 6px 圆角线条、16px 留白、不含文字和元数据，编码后不得超过 64 KiB。
6. 限制最多 8 条笔画、共 512 个简化点，要求至少 3 个不同点、屏幕边界至少一边达到 12 CSS px、坐标有限且宽高比在允许范围内。

请求只包含保留笔画边界的归一化点元组、原始宽高比和上述单色 PNG；绝对白板位置和样式保留在客户端。服务端使用 Zod 重复执行全部限制，不信任浏览器校验结果。预览图不是完整画布截图，服务端不得持久化或记录它。

源指纹按文档层级顺序对选中元素的 `id`、`kind`、`createdAt`、颜色、粗细和全部点（包括压力）进行规范化序列化，再使用 Web Crypto SHA-256 计算。该指纹仅留在客户端，不发送给 AI。

### 4. AI 负责分类，本地确定性重建保持视觉几何

第一阶段分类完全交给 AI。应用不建立第二套本地图形分类器，也不使用闭合度、角点数量或轮廓拟合误差否决 AI 已给出的高置信度已知图形结果。本地几何只负责从源路径估计中心、方向和视觉边界，并生成确定、可持久化的标准路径。

固定置信度阈值为：已知图形至少 `0.80`，未枚举常用符号至少 `0.85`。已知图形重建使用统一几何容差：主轴/次轴或定向宽高比 `1.15`、正多边形边长比 `1.20`、内角偏差 `18°`。AI 常用符号模板仍执行安全和相似度门控：归一化双向 Chamfer RMS 距离不得超过 `0.15`，Hausdorff 距离不得超过 `0.35`。这些值作为命名常量进入夹具测试，后续调整必须伴随测试数据和提示版本变更。

对于椭圆，应用几何代码从原始选中点确定中心和尺寸，并以足够分辨率采样水平长短轴的闭合椭圆，以适配当前与缩放无关的世界坐标模型。近圆结果直接输出正圆。

对于圆形，结果使用原始中心，并以选区宽度和高度的平均值作为直径。数学上的正圆无法同时保留两个不相等的尺寸，因此使用平均直径将视觉变化降至最低。椭圆若主轴/次轴比不超过 `1.15`，也进入同一正圆重建路径。

对于正方形和长方形，几何代码从源点主轴估计尺寸，但输出统一旋转到水平基准。正方形使用拟合宽高的平均值作为边长；长方形若定向宽高比不超过 `1.15` 也升级为正方形，否则输出水平长方形，并强制相邻边垂直、对边平行。平行四边形同样在该阈值内升级为水平正方形，否则输出底边水平的平行四边形。

对于三角形，先从简化轮廓中提取三个稳定角点，再通过最小误差拟合消除边线抖动；近似正三角形输出默认顶点朝上、底边水平的正三角形，否则将拟合后的最低边旋转到水平。对于平行四边形，拟合两组平行边，保持中心、宽高和由原路径估计的倾斜量，同时将底边旋转到水平。

对于五边形和六边形，候选边长比不超过 `1.20` 且内角偏差不超过 `18°` 时，使用原选区中心和统一半径输出底边水平的闭合正多边形。

对于五角星，生成外半径与内半径比例为 `1 : 0.381966` 的十顶点闭合正五角星，并映射到原选区视觉边界。

对于其他常用符号，客户端先对已校验模板与源路径执行归一化双向 Chamfer/Hausdorff 相似度检查，再直接缩放、平移到原轴对齐视觉范围。多路径符号可以生成多条相邻的 `StrokeElement`，所有路径共享原选区样式并作为一个历史操作处理。

标准化点以世界坐标生成，并在末尾重复首点形成闭合。曲线按周长进行有界采样，多边形按顶点和直线边生成。替换结果保留第一条选中笔画的颜色和粗细。生成结果确定且点数有上限，从而在缩放和导出时保持清晰，同时避免持久化过多点。

### 5. 原子替换选中元素并拒绝过期结果

请求开始时，UI 记录选中 ID、对应指纹和最早层级索引。请求处理中，按钮显示忙碌状态并阻止重复请求，但白板其他区域仍可使用。

有效响应返回后，客户端确认所有源元素仍然存在且与已捕获指纹一致。如果选区被编辑、擦除、清空、移动或撤销，则丢弃响应并给出非破坏性反馈。否则移除全部源笔画，并在最早的源层级位置连续插入一条或多条标准化笔画。每条新笔画在提交前只生成一次唯一 ID，所有新笔画共享同一个提交时间作为 `createdAt`；历史记录保存完整 before/after 文档快照，因此重做必须恢复相同 ID、时间戳、点和层级，而不是重新推理或重新生成元素。

替换通过现有 `commitDocument` 作为一条“标准化图形”历史记录提交，全部新元素保持选中，并由现有 300ms 自动保存机制持久化。源元素之间夹有其他元素时，所有替换路径仍从最早源层级连续插入，其他元素之间的相对顺序不得改变。

### 6. 将不支持和推理失败视为无操作结果

服务端返回类型化的可辨识联合结果，而不是向客户端抛出原始绑定错误。AI 无法推断、不支持图形、置信度低于阈值、矢量模板无效、超时、限流和平台故障均不修改源文档。UI 恢复空闲操作并显示约 4 秒后自动消失的 Toast；无法推断时使用明确文案“暂时无法识别这个图形，已保留原图”。服务端截止时间固定为 20 秒，客户端使用 25 秒 `AbortController` 超时和请求序号；迟到或已取消响应必须忽略。

浏览器和服务端均不自动重试，避免重复计费、超时叠加和结果不一致。用户只能在请求结束后再次显式点击。

### 7. 使用不记录路径数据的定向可观测性

服务端日志只包含请求 ID、模型标识符、点/笔画数量、延迟、结果类别、置信度分桶和错误类别。原始点元组、生成的提示内容、白板坐标和用户文档内容均不记录。这样既能监控成本和可靠性，也不会留存绘图数据。

### 8. 通过现有 Worker 项目保持可部署性

实现不需要 `ai` 或 `workers-ai-provider` 运行时依赖；保留现有 `AI` 绑定，新增 `AI_ACTOR_RATE_LIMITER` 和 `AI_COLO_RATE_LIMITER`，并通过 Wrangler 生成 Cloudflare 绑定类型。单元测试模拟原生 AI 与限流绑定。由于开发期间的 Workers AI 推理也会使用 Cloudflare 账户，因此集成冒烟测试使用已认证的远程绑定或已部署预览。

### 9. 固定 Mistral 的生产推理设置

生产模型常量设为 `@cf/mistralai/mistral-small-3.1-24b-instruct`，提示版本设为 `shape-normalization-v7-characters-math`。调用直接使用 `env.AI.run` 和模型原生 `guided_json`，响应再经 Zod Schema 校验。推理为非流式响应、20 秒服务端截止时间，常用符号矢量阶段最多输出 768 Token。提示要求第一阶段只进行扁平分类；第二阶段仅在 `common-symbol` 时生成矢量模板，并明确将斜边且对边平行的四边形分类为 `parallelogram`，将无稳定棱角的连续圆润轮廓分类为 `circle` 或 `ellipse`。

选择该模型的主要原因是：它由 Cloudflare 托管，明确支持视觉输入和 `guided_json`，并在真实手绘矩形测试中以约 2.7 秒延迟返回正确分类。Kimi K2.6 在相同任务中约 30 秒超时；通用 AI SDK Provider 对 Mistral 的结构化参数映射也未能稳定产生合法 JSON，因此两者均不作为生产路径。由于结构化 JSON 模式不采用流式输出，UI 只展示本地忙碌状态，收到完整且校验通过的结果后再提交替换。

本次变更不配置自动模型回退，避免不同模型对同一路径产生不一致结果。模型不可用、结构化输出无法满足或请求超时时，均返回类型化失败结果、显示 Toast 并保持原图不变。模型 ID 和提示版本分别使用命名常量，后续更换模型必须先通过完整测试夹具与远程冒烟测试。

### 10. 在调用 AI 前执行两级费用保护

公开部署没有用户身份系统，因此在严格载荷校验之后、Workers AI 调用之前使用两个 Cloudflare Rate Limiting 绑定。`AI_ACTOR_RATE_LIMITER` 以 `cf-connecting-ip` 和固定操作名组成内部 key，每个 Cloudflare 位置每个来源最多 20 次/60 秒；缺少该请求头时使用共享 `unknown` key。`AI_COLO_RATE_LIMITER` 使用固定 `shape-normalization` key，每个位置最多 120 次/60 秒。两个限制均通过后才允许推理。

限流计数具有 Cloudflare Rate Limiting API 的位置局部和最终一致语义，它不是精确计费系统，但可抑制单来源和单位置的突发滥用。IP 只作为绑定 key 使用，不写日志、不返回客户端。任一限制失败均返回 `rate-limited`，不调用 AI，并显示非破坏性 Toast。`wrangler.jsonc` 为两个绑定分配账户内唯一的正整数 namespace ID，文档说明部署者如与现有命名空间冲突必须修改。

### 11. 使用固定验收语料和发布门槛

夹具至少包含每个已知图形 5 个鼠标/触控笔样本、20 个未枚举常用符号样本、20 个无法推断或不支持样本，以及异常载荷/模板。发布前，已知图形端到端正确替换率必须至少 90%，常用符号至少 80%，不支持样本发生错误替换的比例不得超过 5%，所有异常与过期结果必须 100% 保持原图不变。真实模型冒烟测试必须验证两阶段 Schema 合规、20 秒服务端截止时间、Toast 自动消失、日志脱敏和限流；不满足门槛时不得合并或部署到 `main`。

## Risks / Trade-offs（风险与权衡）

- **模型分类或自由符号推断具有不确定性** → 使用少量示例、`guided_json`、Zod 校验和置信度阈值；不支持或模糊结果显示 Toast 且不执行修改，不通过本地分类器覆盖 AI 判断。
- **AI 生成的符号模板过于复杂、越界或恶意** → 只接受受约束矢量 DSL，双端校验坐标与复杂度，不解析 SVG/HTML，不执行代码，不加载外部资源。
- **正圆或正方形几何与保持不等宽高存在冲突** → 仅在对应近似容差内接受圆形或正方形，并使用平均尺寸；否则分别标准化为椭圆或长方形。
- **AI 标签偶尔省略置信度** → 第一阶段允许 `confidence` 缺省；可识别结果使用 `0.9`，不可识别结果使用 `0`，同时保留公开结果的固定置信度字段。
- **AI 延迟使交互显得缓慢** → 立即显示忙碌状态，保持白板可交互，限制载荷大小和输出 Token，并强制超时。
- **延迟结果覆盖用户的新操作** → 提交替换前立即比较源 ID 和不可变指纹。
- **较大或嘈杂的选区增加成本和提示长度** → 本地简化、限制笔画/点数量、拒绝超大输入，并使用满足质量要求的最小已验证模型。
- **公开 AI 端点被滥用导致拒绝服务或意外费用** → 在推理前执行单来源 20 次/分钟与单位置总量 120 次/分钟的两级 Cloudflare Rate Limiting，并监控 `rate-limited` 与模型用量；保持显式点击且不自动重试。
- **多条选中笔画的样式或意图不兼容** → 要求颜色和粗细一致，并仅将其作为单个聚合图形替换；否则在推理前拒绝。
- **本地或错误配置的部署中缺少 Workers AI 绑定** → 返回类型化不可用结果，记录远程绑定开发方式，生成 Worker 类型，并在部署冒烟测试中验证绑定。
- **生产模型被弃用或结构化输出行为变化** → 使用单一命名模型常量和回归夹具监控；更换模型前必须通过已知图形、自由符号、无法推断和异常模板测试，不在运行时静默回退。
- **日志中出现原始绘图数据** → 只记录数量、时间、为请求生成的 ID 和分类结果。

## Migration Plan（迁移计划）

1. 定义 Mistral 生产模型和 `shape-normalization-v4-two-stage` 提示常量，配置两个 Rate Limiting 绑定并生成 Cloudflare 绑定类型，同时保留现有 Worker 入口、原生 `AI` 绑定和 CSRF 中间件。
2. 在现有选区 UI 后增加共享请求/响应 Schema、256×256 选区预览生成、仅服务端推理/限流适配器、提示和类型化服务端函数。
3. 先增加确定性的几何图形/五角星拟合，以及受约束矢量模板校验、变换和采样测试，再启用文档替换。
4. 接入 Toast、处理中状态和单路径/多路径原子历史替换，然后验证撤销/重做、重新加载持久化、导出及过期响应行为。
5. 部署到 Cloudflare 预览环境，执行已知图形、未枚举常用符号及无法推断输入的真实冒烟用例，检查脱敏日志，再通过现有 `main` 分支部署集成发布。

回滚时移除服务端函数调用，并将选区操作恢复为禁用或隐藏状态。已有标准化笔画仍是有效的版本 1 `StrokeElement` 数据，无需数据迁移或清理。
