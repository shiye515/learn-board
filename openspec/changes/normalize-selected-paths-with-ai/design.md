## Context（上下文）

Canvas Room 将徒手笔画存储为世界坐标中的 `StrokeElement` 点数组。当前选区操作可以生成类似 SVG 的路径字符串，但只会输出到控制台，不会修改文档。应用已经使用 TanStack Start，并以 Cloudflare Workers 为部署目标；`wrangler.jsonc` 也已声明 `AI` 绑定。

新流程将跨越浏览器、类型化 TanStack Start 服务端边界、Cloudflare Workers AI、确定性几何重建、文档历史和本地持久化。模型输出不能直接作为文档数据使用：必须经过 Schema 校验、置信度门控，并由应用代码转换为几何图形后，才能替换用户笔画。

Cloudflare 文档提供了本方案使用的两个集成点：Worker 代码通过 `env.AI` 访问 Workers AI；`workers-ai-provider` 可以封装该绑定，为 AI SDK 提供结构化对象生成能力。本地开发期间调用 Workers AI 仍会访问 Cloudflare 账户并产生用量。

生产推理模型确定为 Cloudflare 托管的 `@cf/meta/llama-4-scout-17b-16e-instruct`。该模型支持视觉输入、Function Calling 和 `guided_json`。请求同时提供简化路径点和仅由选中路径生成的单色预览图：点数据用于保留精确拓扑，预览图用于提升五角星及未枚举生活符号的识别可靠性。

## Goals / Non-Goals（目标与非目标）

**目标：**

- 识别选中的标准几何图形（包括五角星），并允许 AI 推断未预先枚举的生活常用符号，将其替换为安全、规整的矢量路径。
- 保持选中图形的中心和视觉占用范围，以及精确的笔画颜色、粗细、层级顺序、撤销/重做和自动保存行为。
- 将 Workers AI、Rate Limiting 和 Cloudflare 绑定限制在仅服务端边界内，只发送必要的选中几何和选区单色预览。
- 所有模型响应在通过严格 Zod Schema、支持图形检查、置信度检查和源数据时效检查前均视为不可信。
- 使用采样后的 `StrokeElement` 点表示标准化图形，保持现有版本 1 白板文档兼容。
- 提供清晰的处理中和成功反馈；无法推断、低置信度、模板无效、超时、限流或一般错误时显示 Toast，并保持原图不变。

**非目标：**

- 本次变更不自动标准化每一条完成的笔画，也不增加类似 iOS 的长按手势。
- 首个版本不识别手写文字、便签文本、复杂任意插画或要求语义理解的场景图；常用符号是否可转换由模型置信度和矢量模板校验共同决定。
- 不向推理服务发送完整白板、视口、便签内容、本地持久化载荷、笔画颜色或 Cloudflare 凭据。
- 不允许模型返回可执行代码或直接生成白板元素。
- 不新增远程白板存储、协作系统或文档 Schema 版本。

## Decisions（决策）

### 1. 使用类型化服务端函数和原生 Workers AI 绑定

选框按钮调用 TanStack Start POST 服务端函数。共享请求/响应 Schema 放在不依赖运行时的模块中；推理适配器使用 `.server.ts` 后缀，并仅在其中从 `cloudflare:workers` 导入 `env`。处理器通过 `createWorkersAI({ binding: env.AI })` 构造 Workers AI Provider，再由 AI SDK 配合 Zod 输出 Schema 调用 `@cf/meta/llama-4-scout-17b-16e-instruct`。服务端函数继续受 `src/start.ts` 中现有 `createCsrfMiddleware` 保护。

这样可以避免凭据和运行时绑定进入客户端包，保持现有 TanStack Start 应用模型，并遵循 Cloudflare 的 Worker 绑定与 AI SDK 集成方式。直接从浏览器调用 Workers AI REST API 会暴露凭据并绕过应用校验边界，因此不采用。若 Provider 无法传递模型所需的结构化输出参数，可将原生 `env.AI.run` API 作为同一 Llama 4 Scout 模型的调用后备，但仍必须使用相同 Schema 和 Zod 校验，且不得切换到其他模型。

### 2. 使用“已知图形策略 + 受约束 AI 矢量模板”的混合输出

模型接收简化、归一化的点元组，并返回严格的可辨识联合结果：

```ts
type ShapeInference =
  | {
      kind: 'known-shape'
      shape:
        | 'circle'
        | 'ellipse'
        | 'square'
        | 'rectangle'
        | 'triangle'
        | 'parallelogram'
        | 'pentagon'
        | 'hexagon'
        | 'five-point-star'
      confidence: number
    }
  | {
      kind: 'common-symbol'
      symbolName: string
      confidence: number
      paths: Array<{
        closed: boolean
        segments: Array<
          | { type: 'move' | 'line'; to: [number, number] }
          | { type: 'quadratic'; control: [number, number]; to: [number, number] }
          | { type: 'cubic'; controls: [[number, number], [number, number]]; to: [number, number] }
        >
      }>
    }
  | { kind: 'unsupported'; confidence: number }
```

对于已知图形，AI 只负责分类，本地确定性策略负责几何校验与重建。对于未预先枚举但模型能够可靠识别的生活常用符号，AI 可以返回单位坐标中的矢量模板，从而保留一定自由发挥空间。该模板不是 SVG 文本、代码或白板元素，只能由有限的移动、直线、二次曲线和三次曲线段组成。

服务端和客户端都必须使用严格 Schema 校验模板。`symbolName` 必须是 1–64 字符的小写 ASCII slug；每次响应最多 8 条路径、总计最多 32 个段、采样后最多 512 个点。每条路径必须以且只能以一个 `move` 开始，随后至少包含一个可绘制段；端点坐标必须位于 `[0, 1]`，二次/三次曲线控制点允许位于 `[-0.25, 1.25]`。未知字段、非有限坐标、越界坐标、空路径或复杂度超限均视为无效。

通过 Schema 校验后，客户端先对模板可见几何边界重新归一化，再以原选区的轴对齐边界进行缩放和平移；模板必须保持预览图中观察到的方向，客户端不对未枚举符号额外旋转，避免重复旋转。曲线使用自适应细分，每段最多 16 个采样点，且必须遵守 512 点总上限。任何模板都不得携带颜色、粗细、ID、事件处理器、URL、脚本或任意 SVG 标记。

这种混合方式让常见但未列举的符号具备扩展空间，同时将 AI 自由限制在安全的小型矢量 DSL 中。应用继续使用类型化图形策略注册表管理已知标签；新增确定性图形时只需扩展标签、策略和测试夹具，不改变服务端函数、历史记录或持久化流程。

### 3. 归一化并限制请求载荷

只有选中的笔画元素具备资格。便签永不包含在载荷中。选区可以包含一条笔画，或少量颜色与粗细完全一致的笔画；混合样式或包含便签的选区会在推理前被拒绝。

调用服务端前，客户端将：

1. 计算由选中元素 ID 和点数据组成的不可变指纹。
2. 将点转换到选区局部坐标，并缩放到单位边界框。
3. 使用确定性线段简化算法减少点数，同时保留闭合关系和主要极值点。
4. 移除压力、颜色、时间戳、ID、世界坐标位置和无关文档数据。
5. 将所有选中笔画按轴对齐选区等比缩放并居中渲染为 256×256 PNG：白色背景、黑色 6px 圆角线条、16px 留白、不含文字和元数据，编码后不得超过 64 KiB。
6. 限制最多 8 条笔画、共 512 个简化点，要求至少 3 个不同点、屏幕边界至少一边达到 12 CSS px、坐标有限且宽高比在允许范围内。

请求只包含保留笔画边界的归一化点元组、原始宽高比和上述单色 PNG；绝对白板位置和样式保留在客户端。服务端使用 Zod 重复执行全部限制，不信任浏览器校验结果。预览图不是完整画布截图，服务端不得持久化或记录它。

源指纹按文档层级顺序对选中元素的 `id`、`kind`、`createdAt`、颜色、粗细和全部点（包括压力）进行规范化序列化，再使用 Web Crypto SHA-256 计算。该指纹仅留在客户端，不发送给 AI。

### 4. 通过按图形分类的确定性拟合保持视觉几何

本地拟合先按弧长对源路径重采样，避免指针事件密度影响主轴和角点计算。单笔画通过首尾距离判断闭合；多笔画通过端点图连接，端点距离不超过选区对角线的 8% 时允许反转或重排笔画形成轮廓。简单闭合图形若产生分叉拓扑则拒绝。闭合轮廓的最终首尾间距不得超过对角线的 15%。

固定首发阈值为：已知图形置信度至少 `0.80`，未枚举常用符号至少 `0.85`；近圆和近方形的长短轴比例不得超过 `1.15`；已知多边形和五角星的归一化双向 RMS 轮廓误差不得超过 `0.12`；AI 常用符号模板与源路径的归一化双向 Chamfer RMS 距离不得超过 `0.15`，Hausdorff 距离不得超过 `0.35`。这些值作为命名常量进入夹具测试，后续调整必须伴随测试数据和提示版本变更。

对于椭圆，应用几何代码从原始选中点确定中心和主轴，保持拟合后的旋转宽度与高度，并以足够分辨率采样闭合椭圆，以适配当前与缩放无关的世界坐标模型。

对于圆形，只有拟合主轴/次轴比例处于配置的近圆容差内时才接受圆形识别。结果使用原始中心，并以拟合宽度和高度的平均值作为直径。数学上的正圆无法同时保留两个不相等的尺寸，因此通过限制圆形接受范围并使用平均直径，将视觉变化降至最低。超出容差的图形即使被模型标记为圆，也按椭圆处理。

对于正方形和长方形，几何代码先拟合主轴方向与四个角点。正方形仅在边长比例处于近方形容差内时接受，并使用拟合宽高的平均值作为边长；否则在长方形检查通过时按长方形处理。长方形保持拟合中心、方向、宽度和高度，并强制相邻边垂直、对边平行。

对于三角形，先从简化轮廓中提取三个稳定角点，再通过最小误差拟合消除边线抖动；结果保持拟合中心、方向、三顶点相对轮廓和视觉占用范围，不强制转换为等边三角形。对于平行四边形，拟合两组平行边，保持中心、方向、宽高和由原路径估计的倾斜量，同时强制对边平行。

对于五边形和六边形，仅输出正多边形。几何代码根据检测到的角点，对标准模板执行全角度旋转和统一缩放的最小误差拟合，不使用对旋转对称图形不稳定的 PCA 方向作为最终方向。结果生成等边等角的正五边形或正六边形；只有轮廓误差不超过阈值，且输出轴对齐宽、高相对原选区的变化均不超过 8% 时才接受。

对于五角星，本地策略对十个交替角点进行旋转模板最小误差拟合，生成外半径与内半径比例为 `1 : 0.381966` 的闭合正五角星。只有轮廓误差不超过阈值，且输出宽、高变化均不超过 8% 时才接受。

对于其他常用符号，客户端先对已校验模板与源路径执行归一化双向 Chamfer/Hausdorff 相似度检查，再直接缩放、平移到原轴对齐视觉范围。多路径符号可以生成多条相邻的 `StrokeElement`，所有路径共享原选区样式并作为一个历史操作处理。

标准化点以世界坐标生成，并在末尾重复首点形成闭合。曲线按周长进行有界采样，多边形按顶点和直线边生成。替换结果保留第一条选中笔画的颜色和粗细。生成结果确定且点数有上限，从而在缩放和导出时保持清晰，同时避免持久化过多点。

### 5. 原子替换选中元素并拒绝过期结果

请求开始时，UI 记录选中 ID、对应指纹和最早层级索引。请求处理中，按钮显示忙碌状态并阻止重复请求，但白板其他区域仍可使用。

有效响应返回后，客户端确认所有源元素仍然存在且与已捕获指纹一致。如果选区被编辑、擦除、清空、移动或撤销，则丢弃响应并给出非破坏性反馈。否则移除全部源笔画，并在最早的源层级位置连续插入一条或多条标准化笔画。每条新笔画在提交前只生成一次唯一 ID，所有新笔画共享同一个提交时间作为 `createdAt`；历史记录保存完整 before/after 文档快照，因此重做必须恢复相同 ID、时间戳、点和层级，而不是重新推理或重新生成元素。

替换通过现有 `commitDocument` 作为一条“标准化图形”历史记录提交，全部新元素保持选中，并由现有 300ms 自动保存机制持久化。源元素之间夹有其他元素时，所有替换路径仍从最早源层级连续插入，其他元素之间的相对顺序不得改变。

### 6. 将不支持和推理失败视为无操作结果

服务端返回类型化的可辨识联合结果，而不是向客户端抛出原始 Provider 错误。AI 无法推断、不支持图形、置信度低于阈值、矢量模板无效、超时、限流和 Provider 故障均不修改源文档。UI 恢复空闲操作并显示 Toast；无法推断时使用明确文案“暂时无法识别这个图形，已保留原图”。服务端截止时间固定为 8 秒，客户端使用 10 秒 `AbortController` 超时和请求序号；迟到或已取消响应必须忽略。

浏览器和服务端均不自动重试，AI SDK 调用显式设置 `maxRetries: 0`，避免重复计费、超时叠加和结果不一致。用户只能在请求结束后再次显式点击。

### 7. 使用不记录路径数据的定向可观测性

服务端日志只包含请求 ID、模型标识符、点/笔画数量、延迟、结果类别、置信度分桶和错误类别。原始点元组、生成的提示内容、白板坐标和用户文档内容均不记录。这样既能监控成本和可靠性，也不会留存绘图数据。

### 8. 通过现有 Worker 项目保持可部署性

实现将新增 `ai` 和 `workers-ai-provider`，保留现有 `AI` 绑定，新增 `AI_ACTOR_RATE_LIMITER` 和 `AI_COLO_RATE_LIMITER`，并通过 Wrangler 生成 Cloudflare 绑定类型。单元测试模拟推理与限流适配器。由于开发期间的 Workers AI 推理也会使用 Cloudflare 账户，因此可选的集成冒烟测试使用已认证的远程绑定或已部署预览。

### 9. 固定 Llama 4 Scout 的生产推理设置

生产模型常量设为 `@cf/meta/llama-4-scout-17b-16e-instruct`，提示版本设为 `shape-normalization-v1`。调用使用 AI SDK 结构化对象生成和 Zod Schema，并利用模型的 `guided_json` 能力约束可辨识联合结果。推理设置为 `temperature: 0`、`max_tokens: 2048`、非流式响应和 8 秒服务端截止时间。提示明确要求优先返回已知图形、仅在高置信度时生成常用符号模板、保持预览中的方向与路径拓扑，不确定时返回 `unsupported`。

选择该模型的主要原因是：它由 Cloudflare 托管、明确支持 Function Calling 和 `guided_json`，对图形及常用符号具有足够的理解能力，并能在未来需要时接受视觉输入。相较只强调低延迟的轻量模型，本功能更优先保证复杂矢量 Schema 的遵循度和符号推断质量。由于结构化 JSON 模式不采用流式输出，UI 只展示本地忙碌状态，收到完整且校验通过的结果后再提交替换。

本次变更不配置自动模型回退，避免不同模型对同一路径产生不一致结果。模型不可用、结构化输出无法满足或请求超时时，均返回类型化失败结果、显示 Toast 并保持原图不变。模型 ID 和提示版本分别使用命名常量，后续更换模型必须先通过完整测试夹具与远程冒烟测试。

### 10. 在调用 AI 前执行两级费用保护

公开部署没有用户身份系统，因此在严格载荷校验之后、Workers AI 调用之前使用两个 Cloudflare Rate Limiting 绑定。`AI_ACTOR_RATE_LIMITER` 以 `cf-connecting-ip` 和固定操作名组成内部 key，每个 Cloudflare 位置每个来源最多 20 次/60 秒；缺少该请求头时使用共享 `unknown` key。`AI_COLO_RATE_LIMITER` 使用固定 `shape-normalization` key，每个位置最多 120 次/60 秒。两个限制均通过后才允许推理。

限流计数具有 Cloudflare Rate Limiting API 的位置局部和最终一致语义，它不是精确计费系统，但可抑制单来源和单位置的突发滥用。IP 只作为绑定 key 使用，不写日志、不返回客户端。任一限制失败均返回 `rate-limited`，不调用 AI，并显示非破坏性 Toast。`wrangler.jsonc` 为两个绑定分配账户内唯一的正整数 namespace ID，文档说明部署者如与现有命名空间冲突必须修改。

### 11. 使用固定验收语料和发布门槛

夹具至少包含每个已知图形 5 个鼠标/触控笔样本、20 个未枚举常用符号样本、20 个无法推断或不支持样本，以及异常载荷/模板。发布前，已知图形端到端正确替换率必须至少 90%，常用符号至少 80%，不支持样本发生错误替换的比例不得超过 5%，所有异常与过期结果必须 100% 保持原图不变。真实模型冒烟测试必须验证 Schema 合规、8 秒服务端截止时间、Toast、日志脱敏和限流；不满足门槛时不得合并或部署到 `main`。

## Risks / Trade-offs（风险与权衡）

- **模型分类或自由符号推断具有不确定性** → 使用零温度、少量示例、Schema 校验、置信度阈值和本地几何合理性检查；不支持或模糊结果显示 Toast 且不执行修改。
- **AI 生成的符号模板过于复杂、越界或恶意** → 只接受受约束矢量 DSL，双端校验坐标与复杂度，不解析 SVG/HTML，不执行代码，不加载外部资源。
- **正圆或正方形几何与保持不等宽高存在冲突** → 仅在对应近似容差内接受圆形或正方形，并使用平均尺寸；否则分别标准化为椭圆或长方形。
- **AI 标签与轮廓顶点数量不一致** → 在客户端执行闭合度、角点数量、平行/垂直关系和拟合误差检查；未通过时回退到更宽松的兼容图形或保持原图不变。
- **AI 延迟使交互显得缓慢** → 立即显示忙碌状态，保持白板可交互，限制载荷大小和输出 Token，并强制超时。
- **延迟结果覆盖用户的新操作** → 提交替换前立即比较源 ID 和不可变指纹。
- **较大或嘈杂的选区增加成本和提示长度** → 本地简化、限制笔画/点数量、拒绝超大输入，并使用满足质量要求的最小已验证模型。
- **公开 AI 端点被滥用导致拒绝服务或意外费用** → 在推理前执行单来源 20 次/分钟与单位置总量 120 次/分钟的两级 Cloudflare Rate Limiting，并监控 `rate-limited` 与模型用量；保持显式点击且不自动重试。
- **多条选中笔画的样式或意图不兼容** → 要求颜色和粗细一致，并仅将其作为单个聚合图形替换；否则在推理前拒绝。
- **本地或错误配置的部署中缺少 Workers AI 绑定** → 返回类型化不可用结果，记录远程绑定开发方式，生成 Worker 类型，并在部署冒烟测试中验证绑定。
- **生产模型被弃用或结构化输出行为变化** → 使用单一命名模型常量和回归夹具监控；更换模型前必须通过已知图形、自由符号、无法推断和异常模板测试，不在运行时静默回退。
- **日志中出现原始绘图数据** → 只记录数量、时间、为请求生成的 ID 和分类结果。

## Migration Plan（迁移计划）

1. 新增 AI SDK/Provider 依赖，定义生产模型和 `shape-normalization-v1` 提示常量，配置两个 Rate Limiting 绑定并生成 Cloudflare 绑定类型，同时保留现有 Worker 入口、`AI` 绑定和 CSRF 中间件。
2. 在现有选区 UI 后增加共享请求/响应 Schema、256×256 选区预览生成、仅服务端推理/限流适配器、提示和类型化服务端函数。
3. 先增加确定性的几何图形/五角星拟合，以及受约束矢量模板校验、变换和采样测试，再启用文档替换。
4. 接入 Toast、处理中状态和单路径/多路径原子历史替换，然后验证撤销/重做、重新加载持久化、导出及过期响应行为。
5. 部署到 Cloudflare 预览环境，执行已知图形、未枚举常用符号及无法推断输入的真实冒烟用例，检查脱敏日志，再通过现有 `main` 分支部署集成发布。

回滚时移除服务端函数调用，并将选区操作恢复为禁用或隐藏状态。已有标准化笔画仍是有效的版本 1 `StrokeElement` 数据，无需数据迁移或清理。
