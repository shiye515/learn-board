## Context

现有项目是 TanStack Start + React 19 + TanStack Router 的演示应用，根页面包含传统导航、卡片和示例 server functions。目标产品则是无页面滚动、以 Canvas 为主的全视口工具，视觉基准来自 2026-08-06 访问的 Ziteboard 繁体中文界面：白色画布覆盖视口，约 20px 高的黄色连接状态条置顶，右上从约 `x=808` 开始排列 48px 圆形按钮，右下提供灰色视图导航按钮。白板交互高度依赖 Pointer Events、Canvas 2D、设备像素比和浏览器存储。

实现必须保留 TanStack Start 的根文档 SSR、文件路由和现有 Node/srvx 部署形态，但不得让 Canvas 或浏览器 API 在服务器执行。首阶段为单机白板，不建立用户、权限或协作后端。

## Goals / Non-Goals

**Goals:**

- 在桌面基准视口 `1312×872` 上还原参考页面的工具位置、尺寸、间距、颜色、阴影和状态层级，并为常见移动端/平板视口提供等价可用布局。
- 建立可扩展的白板文档模型，使渲染、输入、历史和持久化相互解耦。
- 提供低延迟的画笔、橡皮、便签/文本、选择、移动、撤销/重做和视口操作。
- 在刷新或重新打开页面后恢复本地白板，并支持导出内容区域 PNG。
- 维持严格客户端白板边界，生产构建及 Node 启动流程保持可用。

**Non-Goals:**

- 不连接 Ziteboard 的 API，不复制其代码、私有素材、商标或专有协议。
- 不实现账号、订阅、远程存储、多人实时同步、音视频或权限控制。
- 不在首阶段实现公式编辑器、图表绘制器、激光笔或完整专业版工具集。
- 不保证与 Ziteboard 文件格式互操作。

## Decisions

### 1. 使用原生 Canvas 2D，并以结构化文档模型作为事实来源

文档以带版本号的 `WhiteboardDocument` 保存，元素为 stroke、note/text 等判别联合类型；Canvas 只是当前文档和视口变换的投影。这样历史、导出、恢复和将来协作都基于操作/模型，而不是像素快照。

备选方案是引入 Fabric.js/Konva/Excalidraw。它们能缩短部分交互开发，但会带来较大的依赖、默认交互与目标视觉不一致，并限制对像素级工具外壳和渲染行为的控制，因此本阶段不用。

### 2. 分离文档坐标与屏幕坐标

`ViewportTransform { x, y, scale }` 负责屏幕和世界坐标互换。所有输入在进入工具状态机时转换到世界坐标，渲染时统一应用变换。缩放以指针位置为锚点，缩放范围限制为 10%–800%，平移不设固定世界边界。

### 3. 使用单一 Pointer Events 输入管线和工具状态机

鼠标、触控笔、触摸都进入统一控制器；控制器处理 pointer capture、压力、取消事件和多指手势，再委派给 active tool。绘制期间只更新正在进行的临时元素，pointerup 后提交一个原子历史操作，避免每个采样点都创建历史记录。

### 4. 高 DPI 分层渲染

Canvas backing store 按 `devicePixelRatio` 调整，CSS 尺寸保持视口像素。静态文档层与当前手势/选择装饰层分开绘制，通过 `requestAnimationFrame` 合并刷新；ResizeObserver 处理窗口变化。首阶段不使用 OffscreenCanvas，以降低兼容性与测试复杂度。

### 5. 历史记录保存可逆命令，持久化保存文档快照

撤销/重做栈保存 add/update/remove/clear 命令，默认最多 100 步；本地持久化经过 300ms 防抖，保存版本化文档和视口。内容优先使用 IndexedDB，若不可用则回退到 localStorage；损坏或未知版本不阻止打开空白板。

### 6. 根文档 SSR，白板工作区使用客户端渲染边界

`__root.tsx` 继续输出完整 `<html>`、head、脚本和无闪烁背景；`/` 白板路由设为 `ssr: false` 或将 Canvas 子树放在明确的 client-only 边界。加载占位必须与最终白色画布及工具栏骨架同尺寸，避免 hydration layout shift。路由与部署配置不改为另一框架或 SPA-only 构建。

### 7. 视觉基线以测量 token 和截图回归固定

样式集中定义尺寸/颜色 token：状态条约 20px、主要圆形按钮 48px、按钮间距 16px、白色/浅灰面、深灰图标、细灰边框和轻阴影。实现时保存参考视口截图并对本地页面进行同尺寸截图比对；非商标化图标使用统一 SVG 线条集合。

### 8. 未实现入口保持可见但明确禁用

为了保持参考工具菜单的结构，可显示邀请、仅查看、同步视图等入口，但必须带“暂不可用”状态、不可触发网络或误导用户。核心工具必须完整可用后再考虑扩展。

## Implementation Priority

### P0 — Core usable whiteboard

- 全视口白板外壳和客户端 Canvas 边界。
- 结构化文档模型、高 DPI 渲染、画笔和橡皮。
- 平移、滚轮缩放、视图重置和适配内容。
- 撤销/重做及基本键盘快捷键。
- P0 完成时必须已能在生产构建中连续完成“绘制 → 擦除 → 平移/缩放 → 撤销/重做”。

### P1 — Complete editing session

- 点击/框选、移动、删除。
- 便签创建与文本编辑。
- 清空确认、本地自动保存和刷新恢复。
- P1 完成时必须能完成一次不丢数据的完整单机白板会话。

### P2 — Product finish

- PNG 导出、存储异常反馈、触控细节。
- 移动端收纳布局、菜单和所有视觉状态精修。
- 截图回归、性能验证、无障碍和生产检查。

后续优先级不应阻塞前一优先级的可演示验收；若实现时间受限，必须先交付通过验收的 P0，再报告 P1/P2 未完成项。

## Definition of Done

该变更只有同时满足以下条件才视为完成：

- `pnpm typecheck`、单元测试、浏览器测试和 `pnpm build` 全部通过。
- `pnpm start` 启动的生产版本可访问根路由，SSR 文档正常，白板客户端初始化无 hydration 错误。
- 浏览器控制台在核心验收流程中没有 error 或未处理 Promise rejection。
- 鼠标可以完成绘制、擦除、选择、移动、平移、缩放、撤销和重做；清空必须经过确认。
- 保存完成后刷新页面，元素与视口正确恢复；本地存储不可用时不会阻塞编辑。
- `1312×872` 四个桌面参考状态和 `390×844` 移动端状态均生成 actual 截图，关键布局几何误差不超过 2px。
- 页面及产物中不存在旧 Learn Board 导航、页面、示例文案、无用 server functions 或卡片样式。
- 页面不使用 Ziteboard 名称、Logo、私有图标/素材，不调用其 API，也不在保存或导出时发送白板内容。

## Delivery Checkpoints

实现应按以下可独立验证的节点提交；每个节点应保持类型检查和已有测试通过：

1. `whiteboard-model`: 文档类型、坐标变换、命令历史及单元测试。
2. `whiteboard-shell`: SSR 文档壳、客户端白板边界、工具栏/菜单和视觉 token。
3. `canvas-tools`: Canvas 渲染、视口、画笔、橡皮、选择、便签和快捷键。
4. `persistence-export`: IndexedDB/localStorage 恢复、状态提示和 PNG 导出。
5. `visual-verification`: 响应式调整、参考/实际截图、浏览器测试和生产烟雾测试。

检查点描述的是提交边界，不授权自动推送远程分支；由实现者在当前工作流允许时创建本地提交或保持清晰的分阶段变更。

## Risks / Trade-offs

- [像素级相似度会受浏览器字体和平台抗锯齿影响] → 使用 SVG 图标、固定几何 token、基准 Chrome 视口和截图容差；验收关注位置/尺寸/色彩及交互状态，不要求逐像素抗锯齿完全一致。
- [长时间绘制产生大量点导致重绘变慢] → 对采样点做距离阈值过滤与简化，按可见范围绘制，限制历史深度，并把性能场景纳入验收。
- [localStorage 容量不足] → 优先 IndexedDB，保存失败时显示非阻塞状态并保留内存文档。
- [触控绘制与浏览器滚动/缩放冲突] → 工作区使用 `touch-action: none`，仅在画布范围内捕获手势，并提供显式移动工具。
- [清除与擦除可能造成不可恢复损失] → 清除需要确认且进入撤销栈；橡皮操作按元素/笔划分段记录可逆变更。
- [客户端白板造成 SSR 空壳] → SSR 输出稳定画布背景和工具骨架，Canvas 初始化后原位接管。

## Migration Plan

1. 在替换页面前新增文档模型、坐标变换、历史和存储单元测试。
2. 新建白板路由组件与样式，在根路由移除旧导航并保留 SSR 文档壳。
3. 接入 Canvas 渲染和输入工具，完成桌面与触控验收。
4. 删除旧 Demo 路由、server functions、schema 和无用 CSS；生成新的 route tree。
5. 执行类型检查、生产构建、浏览器功能测试和 `1312×872` 截图回归。
6. 若上线后需回滚，恢复上一版本构建即可；本地白板数据使用独立版本化 key，不影响旧 Demo。

## Open Questions

- 首阶段便签采用纯文本固定样式；富文本和便签颜色扩展留待后续变更。
- PNG 默认导出所有内容的紧致包围盒并留 32px 边距；后续可增加“当前视口”导出选项。
- 多人协作若后续加入，应基于当前结构化文档/操作模型设计独立同步规格，而不是直接扩展本地存储层。
